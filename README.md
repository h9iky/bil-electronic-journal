# 🎓 BIL — Электронный журнал

> **BIL — Electronic Journal** · **BIL — электрондық журналы**
>
> Электронный дневник/журнал школы в духе bilimclass.kz, но со своими фишками:
> гибкие СОР/СОЧ, активность 1–10, поведение отдельной категорией, «потенциальная
> оценка», посещаемость и домашние задания. Три языка из коробки:
> 🇷🇺 Русский · 🇰🇿 Қазақша · 🇬🇧 English.

Учебный/портфолио-проект для поступления в университет.

---

## ✨ Возможности

- 🔐 **Три роли**: ученик, учитель, админ — разграничение доступа на сервере.
- 🪪 **Регистрация с паролем**: ученик выбирает класс из справочника, учитель заходит
  без класса; пароль хранится **scrypt-хешем** (соль на каждый), открытый текст — нигде.
  Демо-кнопки на логине остаются для показа проекта в один клик.
- 🗂 **Всё по классам**: ученики внутри класса, без поиска по общей свалке.
- 🏫 **Справочник классов**: админ заводит классы 7–11 × A–E на учебный год
  (латиница, `10A`); имя собирается из номера и буквы, дубли в году исключены индексом.
- 📊 **Гибкие СОР/СОЧ**: учитель сам задаёт максимум — из 10, 20, 30; проценты и
  четвертная считаются автоматически по настраиваемым весам и порогам.
- ⭐ **Активность 1–10** — отдельная метрика ученика по предмету (не оценка).
- 🧭 **Поведение** — отдельная категория (замечания/поощрения), не смешивается с оценками.
- 💡 **«Потенциальная оценка»** — рекомендация учителя на основе активности/поведения;
  учитель сам применяет её или отклоняет. **Принятое** предложение напрямую
  подменяет итог четверти по предмету.
- 🗓 **Посещаемость** — отметки по дням (`Присутствовал / Отсутствовал / Опоздал / Уважительная`).
- 📚 **Домашние задания** — учитель задаёт на урок (класс × предмет × день), ученик
  видит раздел **«Что задано»** с дедлайнами и пометками «Сегодня / Завтра». День
  общий с посещаемостью (`?date=`), поэтому на один урок — и отметки, и задание.
- ⌨️ **Excel-подобная навигация** в журнале: Enter/↑/↓ между строками, ←/→ по краям,
  `Esc` — откат, вставка блока из буфера раскладывает баллы по сетке.
- 🌍 **Три языка**: RU / KZ / EN (переключатель в интерфейсе).

## 🚀 Запуск

```bash
# 1. Зависимости
npm install

# 2. Переменные окружения
cp .env.example .env        # при необходимости поменяй SESSION_SECRET

# 3. База данных (создаст prisma/dev.db и сгенерирует клиент)
npx prisma migrate dev

# 4. Демо-данные (класс, ученики, работы, активность, поведение, посещаемость, домашка)
npm run db:seed

# 5. Дев-сервер
npm run dev
```

Открыть: **http://localhost:3000** → редирект на `/ru`.

> Хост `bilgrade` (используется в демо-деплое) добавляется скриптом
> `sudo bash scripts/setup-hosts.sh`.

### Демо-вход

Паролей пока нет — это демо-режим для защиты проекта. На странице входа три
кнопки-роли выполняют вход в один клик:

| Роль | Аккаунт |
|---|---|
| Ученик | `student@bil.edu.kz` |
| Учитель | `teacher@bil.edu.kz` |
| Админ | `admin@bil.edu.kz` |

Права всё равно проверяются на сервере при каждом действии.

### Модель данных (кратко)

`User` (STUDENT/TEACHER/ADMIN) · `Klass` (7–11 × A–E, уникален в рамках года) · `ClassSettings` (веса, пороги, лимиты)
· `Subject` · `Section` · `Enrollment` · `Teaching`
· `Assessment` (FORMATIVE/SAS/SAT, `maxScore` задаёт учитель) · `Grade`
· `ActivityScore` (1–10) · `BehaviorRecord` (POSITIVE/NEGATIVE/NEUTRAL)
· `ProposedGrade` (потенциальная оценка) · `Attendance` (посещаемость по дням)
· `GradeGoal` (цель ученика по предмету) · `Homework` (домашнее задание на урок).

> SQLite не поддерживает `enum`, поэтому «перечисления» — это строки,
> валидируемые union-типами и type-guard'ами в `src/lib/constants.ts`.

## 🧮 Логика оценивания

Вся математика — в `src/lib/grading.ts` (ни один компонент не считает проценты сам).

```
SAS%  = Σ(баллы СОР) / Σ(макс СОР) × 100
SAT%  = балл СОЧ / макс СОЧ × 100
Четвертная% = wSAS·SAS% + wSAT·SAT% + wFORM·FORM%

< 40%  → 2     40–64% → 3     65–84% → 4     ≥ 85% → 5
```

Веса, пороги, округление и лимиты работ — **в настройках класса** (`ClassSettings`),
а не в коде: школы трактуют по-разному. Дефолты — SAS 50% / SAT 50% / формативка 0%,
пороги 40/65/85, округление `HALF_UP`.

Несданная работа (`score = null`) не тянет процент вниз — это «нет данных», а не ноль.

**«Потенциальная оценка»**: пока предложение `PENDING`/`REJECTED`, итог считается
по формуле. Как только учитель **принимает** его (`ACCEPTED`), оно напрямую
подменяет итог четверти по предмету (`effectiveQuarterGrade` в `grading.ts`).
Проценты остаются расчётными — подменяется именно оценка-итог.
